# Implementation status: 0.14.0

The local application uses browser-native HTML, CSS, JavaScript, SVG and
MathML. There are no runtime packages, network calls, accounts or API keys.
The build compiles the complete canonical card records into a classic script,
then embeds the app code, styles and catalog into one offline `dist/index.html`.
No mathematical or executable code is evaluated from content records.

Eighteen supplied draft cards are available: function composition, real
logarithms, derivatives at a point, ratio and scale, linear models, exponential
change, chaos theory, fractal geometry, wave interference, binomial probability,
vector rotation, the Pythagorean theorem, integration and accumulation,
quadratic optimization, complex multiplication, Bayes’ theorem, graph shortest
paths and resonance. They contain 94 worked examples and 122 model fixtures
(104 numeric outputs and 18 invalid or undefined cases). The 187-entry coverage
inventory contains eighteen draft specimens and 169 planned entries; it does
not represent 187 implemented cards.

## Canonical content and projections

`content/cards/*.json` and `content/sources.json` are the single content source.
They retain draft status, recorded revisions, historical research gaps and
independent review gaps. Original handoff provenance remains intact.
Implementing a renderer does not promote the
underlying claims or rewrite their original source history.

`python3 tools/build.py` regenerates `src/catalog.js`, the 112 inert BOH Markdown
documents in `export/`, and the standalone application in `dist/`. It uses only
the Python standard library and rejects unsupported model bindings, duplicate
identities and unresolved source references. Full schema checks are separate:

```
python3 -m pip install -r requirements-checks.txt
python3 tools/check.py
node --test tests/*.test.mjs
```

The full check validates JSON Schema 2020-12, cross-references, AST scope and
arity probes, numerical fixtures, deliberately invalid contract mutations,
complete string payload preservation, deterministic written exports and both
BOH metadata validators pinned to commit
`aa3d4fcae554a5d39bde0aa7dba1f7ab584854b5`.

Source-to-catalog equality and repeated standalone builds are regression
checks. Build and export manifests use content hashes; no current timestamp
enters generated bytes.

## Modular stories and read-along views

`src/module-registry.js` defines validated module registration and independent
instances. `src/playground-modules.js` adapts all eighteen topics to it, and
`src/playground.js` builds controls and views from descriptors. Modules supply
pure evaluation and rendering; the host owns motion, text pacing, input,
focus, and cleanup. Empty control/sweep arrays support static views. Optional
inspectors own their specialized camera updates. The separate square-area
example mounts a nineteenth module twice without editing the host. See
[the module contract](PLAYGROUND_MODULES.md) and
[the sandbox](../examples/module-sandbox.html).

`src/semantic-links.js` selects exact `data-quantity` scene marks, with
authored grammar mappings in `src/symbol-bindings.js`. This complements
broader story-stage emphasis without conflating individual quantities.

## Explicit workspace connections

`src/module-ports.js` declares quantity metadata for the eighteen installed
modules. Each optional port names a numeric parameter or model result, its
quantity type, exact unit identifier, and meaning. The module registry checks
this metadata at registration; the separate nineteenth-module sandbox can
continue without ports or a connection UI.

`src/workspace-links.js` checks compatible quantities and coordinates one
explicit connection between two independent slots. It has no DOM, listeners,
or animation clock. A source input or calculated output can feed a receiving
input only when the quantity types and units match exactly. Its pure check
validates the source value, receiving parameter bounds, and receiving model
domain without mutating either slot. There is no implicit conversion,
rounding, clamping, self-link, cycle, or multiple-link network.

The scoped UI in `src/workspace-panel.js` offers A → B or B → A, quantity
meanings, current readings, and visible independent/connected/paused states.
If a value leaves the permitted range or domain, the connection retains the
last valid receiving value and resumes when valid. Editing the receiving key
disconnects; unrelated controls and view changes keep the connection. Slot
removal, module identity replacement, or leaving Workbench destroys it.

The host controller's `applyParameters` validates a merged parameter copy
atomically, pauses receiving playback, and preserves its selected view and
comparison pin. Incoming writes use the existing smooth follower without
emitting another change callback; numerical text keeps its 250 ms cadence.
The link engine enforces valid mathematical outputs separately from the host's
structural parameter validation, so ordinary domain-failure demonstrations
remain available when a learner edits a module directly.

Live connections close when the workbench is left. An explicit saved workspace
can retain its descriptor and exact viewing context for a later restore; the
individual notebook format remains separate. Numerical linking does not
establish a physical or empirical relationship between illustrative stories.

## Private saved workspaces

`src/workspace-store.js` owns versioned workspace records in a separate browser
storage key. A record contains two ordered slots with exact module identity and
version, complete parameters, selected view, camera, comparison baseline, and
portable inspector state. A connection descriptor may be active or blocked;
blocked values retain the last receiving state. The store validates current
implementations strictly while preserving structurally safe unavailable
versions as readable/exportable data. Backup imports merge atomically by stable
identity, reject conflicting records, and never restore automatically. Corrupt
storage exposes its original untouched bytes through a recovery action.

`src/workspace-runtime.js` separates saved data from mounted controllers.
Capture pauses both slots before reading their exact values and view state.
Restore preflights the complete record and implementation availability before
pausing or changing live slots. It captures a rollback configuration, delegates
synchronous replacement to the app, and rebuilds the previous state on failure.
A failed rollback returns recovery configuration data rather than silently
discarding the prior experiment.

`src/workspace-library.js` and its stylesheet supply a compact explicit save
row, named-record selection, restore, guarded deletion undo, backup controls,
compatibility explanations, and readable saved configuration. The library
does not own model evaluation or mounting. It detaches its local listeners
and ignores pending imports after disposal. Saved-record actions remain
separate from the Notebook's individual observations and exports.

The host's `getViewState`/`restoreViewState` APIs copy or validate the selected
representation, camera, comparison pin, and inspector state without outgoing
parameter callbacks. Module-owned inspector validation keeps fractal zoom and
comparison, and chaos trace disclosure, out of topic-specific host branches.
Saved links restore without writing a new target value; a blocked link remains
blocked until ordinary valid source changes allow it to resume.

This release saves explicit named configurations, not an autosaved live session.
Restored workspaces start paused. Playback state/speed, guided predictions, and
transient focus are not captured. The [workspace format](WORKSPACE_FORMAT.md)
defines the portable data contract. T15 selected exports and revision comparison,
T12 learning/accessibility qualification, and independent content review remain
open. Graph data alternatives and a focused learner walkthrough are the next
implementation priorities.

## Story components

Each card has an original four-stage practical story beside a contextual scene.
`src/life-stories.js` holds the original six immutable stories.
`src/discovery-stories.js` holds six discovery stories, and
`src/frontier-stories.js` adds six stories about accumulation, optimization,
complex numbers, conditional probability, networks and driven motion. The new
providers also include quantity meanings and calculation stages.
`src/story-library.js` combines these providers without
altering their authored records. `src/life-story.js` mounts the reading controls,
stable quantity tokens, playback and explore/capture callbacks. `src/story-journey.js` keeps
step selection and authored progress boundaries separate from the UI and clock.
Back and Next choose a stage; Play this step stops at its endpoint, while
whole-story playback follows the sequence. Read this step mirrors the current
explanation and formula beside the scene and starts open on phones.

`src/calculation-flow.js` mounts three small input, operation and shape stages.
Playback and manual changes start a bounded trace: input at the beginning,
operation after 650 ms, and output after 1400 ms. It stops after the output
selection; Trace it restarts it. Stage selections focus semantic scene roles
without evaluating formula text or changing model parameters. Values come
from the story's shared 250 ms readable-value cadence. Reduced-motion mode
selects the result directly, and destruction cancels any pending frame.

`src/story-links.js` supplies quantity names, meanings and semantic scene roles,
including metadata authored by the discovery and frontier story providers.
It keeps position, finite-interval average speed and instantaneous speed
distinct. `src/story-scenes.js`, `src/everyday.js`, `src/discovery.js`,
`src/frontier.js`, `src/visuals.js` and `src/spatial.js` render contextual,
geometric, graph and spatial views from shared model values.
`src/model-registry.js` routes the everyday, discovery and frontier providers
through their common model API; the original three model implementations remain
in `src/models.js`. Validation, controls,
numeric evaluation and SVG rendering remain bounded and allowlisted.
Narrative formula strings are never executed.

`src/scene-input.js` handles pointer and keyboard scene controls. `src/motion.js`
follows continuously changing display values and paints gradients, while
`src/readable-values.js` gives numerical text a calmer reading cadence.
Geometry can move each frame without replacing explanation nodes or pulsing
their brightness. Exact formula identities remain exact; rounded moving
evaluations can show an approximation sign. Saved experiments retain validated
target values. Reduced-motion behavior and lifecycle cleanup belong to the
controllers and motion layer. See `docs/EVERYDAY_STORIES.md` and
`docs/VISUAL_SYSTEM.md` for the detailed contracts.

## Independent scene inspection

`src/fractal-lens.js` is a pure Koch camera. Its bounded affine transform is
the identity at 1× and follows the first nested third of the top edge at 3×,
9× and 27×. The same motif fills the same viewing width at those stops. A
fixed scene clip contains the magnified geometry. The minimap draws the whole
outline with the exact inverse camera window in gold; original coordinates
and perimeter values do not change. This is magnification of a finite outline,
not dynamically unbounded recursion. `paint(container, {zoom})` updates the
retained camera transform and locator window directly. Main and overview views
share one geometry definition through SVG `use` references, so camera-only
movement does not regenerate or reconcile thousands of contour points.

The optional Compare repeating edges view uses three clipped cameras on that
same retained contour. The original edge, first third and first ninth appear
at equal viewing widths. `comparisonRegions` supplies their source bounds,
transforms and remaining finite detail; `comparison` renders the labeled
windows. Fewer completed refinements remain in a smaller source region, so
the labels distinguish repeated structure from an infinite-detail claim.

`src/scene-inspector.js` and its stylesheet supply small reusable controls for
stories and playgrounds. `mount` returns `viewOptions`, `update`, `settle` and
`destroy`. Fractal view options contain `lens.zoom` and an optional
`lens.compare` flag; the controller sends an explicit `{depth: 5}` mathematical
update for Refine to level 5. Camera
changes use a 90 ms response with a 450 ms settling deadline and their own
250 ms reading pacer. The mathematical shape follower retains its 45 ms
response and 240 ms settling deadline. Camera values never enter the model
parameter validator or notebook snapshot.

For chaos, the inspector shows both starts at seven significant digits, the
initial gap, current gap and their ratio. The scene pairs a population plot
with a synchronized gap-history plot, and story controls expose seed and tiny
starting difference. Replay preserves those selected starts. Both views use the
same deterministic orbit values and interpolated generation cursor. Small
numbers remain readable without adding another simulation or idle clock.

`src/chaos-trace.js` supplies a pure `snapshot(parameters, result)` over those
same evaluated orbit arrays. It validates the bounded states and recurrence,
then returns two rows containing whole-generation input, remaining fraction,
growth factor and next iterate, together with endpoint and current gaps.
At generation zero it exposes 0→1 with interpolation progress zero. At a
positive integer g it retains g−1→g at progress one; between integers it uses
the neighboring whole markers. The final supported cursor therefore shows
35→36. Current gap is the absolute difference of interpolated populations,
including zero at a crossing, rather than an interpolation of endpoint gap
magnitudes. Invalid or inconsistent input produces an unavailable snapshot.

`src/story-scenes.js` projects that snapshot into named story quantities.
The chaos calculation now substitutes actual A/B inputs into the same rule
and displays the next iterates and gap. These discrete quantities retain
seven significant digits when displayed, while saved model values retain
their original precision. Fractional cursor readings remain separately named.

The inspector's One generation → action requests the next whole generation
through the existing mathematical parameter callback and opens Follow one
generation. It preserves the current starts and rate, and is disabled at 36.
The disclosure shows the two substituted calculations and endpoint gaps.
Only while open, `{chaosTrace: true}` adds highlighted whole-step plot segments
and hollow result markers. Closing it returns the scene to its existing
emphasis. The helper owns neither a DOM nor a clock; inspector viewing flags
remain outside model parameters and notebook snapshots.

## Boundaries

The notebook remains a separate browser-local data store. Personal observations
and conjectures are not read by the content exporter. Notebook backups are
explicit user exports, and restoring one validates the model/card identities.

History is deliberately incomplete in the retained specimens. The interface
must show those gaps and must not invent an origin narrative. Mathematical
examples remain draft derivations pending independent review.

BOH metadata validation is static compatibility evidence only. No running BOH
instance, ingestion, indexing, chunk retrieval, revision reopening or Paul's
live corpus was exercised. Exported Markdown carries draft/supporting/
non_authoritative posture and complete written experiment recipes.

Automated model and DOM checks cannot establish pedagogical effectiveness,
historical correctness, proof, universal accessibility or real-world validity
of constructed application examples. Manual assistive-technology review remains
a separate unfinished gate.

The eighteen practical stories use chosen values and explicit assumptions; they are
illustrative applications, not observed cases or measured systems. Fractional
photo-resize passes explicitly interpolate between completed integer resizes.
Final pixel rounding, physical validity and perceived image brightness remain
separate from the ideal numerical models.

The logistic simulation is finite and deterministic. Its fractional generation
coordinate interpolates neighboring iterates; the picture is not a proof of
chaos or a fitted population forecast. Koch integer levels use the recursive
edge rule, while fractional levels raise the next triangular bumps and report
the actual current path length. The Sierpiński inset is a separate finite
construction. Binomial expectation is a mean across comparable trays rather
than an outcome guarantee. The wave probe's signed sample is distinct from
the resultant wave amplitude, and rotation keeps both endpoint coordinates
distinct from the fixed arm length.

The accumulation story uses forward velocity, making its velocity–time area
both displacement and distance. The garden optimum compares rectangles under
a fixed perimeter; it does not optimize over all possible shapes. Complex
multiplication displays a pair of coordinates and distinguishes scale from
angle; zero has no rotation angle. Bayes’ theorem uses stipulated inspection
rates and normalized population fractions, not measured diagnostic performance.
Shortest-path edge weights are positive additive walking times, and the
network layout is schematic. A tie may have multiple minimizing paths.
Resonance displays separate normalized steady-state predictions with positive
damping; it does not simulate startup transients or certify physical limits.
Its displacement-amplitude peak depends on damping and can lie below a drive
ratio of one.

Narrow-viewport browser checks are limited layout evidence. Physical-device,
cross-browser and assistive-technology qualification remain separate gates;
this document does not substitute for the release validation record.
