# Math index, notation and shared search — 0.22.0

The index is a reference provider that can be used independently of the page
renderer. The shared search adapter combines that provider with real cards and
atlas areas. Neither provider starts an animation, accesses storage, or requires
a browser when its script is loaded.

This release projects **409 entries** over 38 draft cards: **389 authored
definitions** and **20 contextual entries for exact card notation**. The common
reference covers all 24 standard Greek letter names in both cases, basic and
compound operations, grouping, set/logic notation, units and typed/TeX forms.
Set, descriptive-statistics and algorithm-analysis vocabulary connects the new
atlas-gap lessons to their existing prerequisites and related meanings.

The completed 29-card pre-expansion checkpoint had 355 entries (335 authored
and 20 contextual). Its [sealed audit](NOTATION_GATE_BEFORE_EXPANSION.json)
records the required notation-first sequence. Current coverage follows the
[finite notation contract](SYMBOL_NOTATION_COVERAGE.md), with an expanded
[release report](NOTATION_COVERAGE_0_22_0.json). This is a reference for the stated
current-app/common baseline, not a dictionary of every mathematical use.

The 0.20.0 checkpoint remains recorded separately: 32 cards, 372 index entries,
29,760 occurrences and 826 normalized forms with no unresolved/callable reviews.
A later batch extends the corpus rather than rewriting that earlier evidence.

## Atlas-gap reference expansion (0.22.0)

Twenty-three new readers extend the reference to 409 entries. There are now
243 authored Related definitions groups.

The new cards introduce finite membership and cardinality, descriptive sample
and population summaries, and a declared linear-scan cost model. Readers cover
the universal set, cardinality, arithmetic mean, population, sample, population
and sample means, signed mean difference, data value, sample size, zero-based
index, input size, algorithm, operation count, cost model, linear time, census,
sample statistic, population parameter and asymptotic bound notation. Every actual-use link comes from authored card
mathematics or learner-facing explanation, not incidental metadata.

Exact local meanings matter. `|A|` and `|R|` count members rather than take a
scalar absolute value. `∑xᵢ` and `∑Xᵢ` use the summation operator ∑, distinct
from Greek capital Σ. Sample mean `x̄` is not complex conjugation; population
mean `μ` retains its own meaning alongside the Greek-letter reader. A zero-based
starting index identifies a label, not a sample size or measurement.

In the scan lesson, `w(n)` counts chosen basic inspections, `c` is a stipulated
cost in ms/item, and `T(n)` is modeled time in ms. `O(n)` and `Θ(n)` are
asymptotic classes, not ordinary numeric function outputs. Typed/TeX variants
retain these contextual roles, and cardinality/mean/bound searches do not claim
unrelated absolute-value, conjugate or function uses.

The known twelve-crate population and deterministic cyclic selection support
exact descriptive comparisons. They do not create random sampling, confidence
intervals or an unbiased-estimator claim. The full scan supplies an operation
count formula for every positive integer input size; a bounded drawing or finite
plot alone is not an asymptotic proof.

## Local predictions and discrete optimization (0.21.0)

Fourteen new readers explain gradient descent, objective/cost function, step
size, iterate, iteration index, convergence, coordinate contraction, iteration
stability, strict convexity, approximation error, overshoot, oscillation and a
descent direction, plus the shifted logarithmic display. Existing direction, gradient, unit-vector, increment and
linear-approximation readers gain the new actual card uses.

The tangent plane uses `L(x+Δx,y+Δy)` at an absolute query point; its signed
residual `R` is actual minus predicted height. The finite offsets `Δx` and `Δy`
are not silently interpreted as infinitesimals. Directional `u` is a unit vector,
while `DᵤF` is a scalar slope. Gradient descent keeps `C(xₖ,yₖ)` as cost, `∇C` as
a vector, `η` as step size and integer `k` as completed updates. These roles do
not merge with binomial choice, unrelated R labels or generic variable prose.

The 0.21.0 report is generated by `python tools/check.py` at
`docs/NOTATION_COVERAGE_0_21_0.json`. It checks 22,182 selected fields, including
20,172 public runtime fields and 874 reference fields. All 36,609 mathematical
occurrences across 876 normalized forms resolve, with zero unresolved/callable
reviews. Its 751 formatting records and 58 reviewed gesture-icon exclusions
remain separate. Reference sources and related definitions remain separate from
canonical mathematical relationship claims.

There are 219 authored entries with Related definitions groups. Exact indexed
forms restrict their card-use projection to actual matching compounds: cost
`C(xₖ,yₖ)` does not become binomial choice, and initial `x₀` is not inferred
from unrelated `W₀` or `V₀` labels. Greek η retains its letter reader alongside
its local step-size meaning. No new public index API is required.

The descent Graph uses a declared shifted natural-log display ln(1+C) of
normalized dimensionless cost. It maps C=0 to zero and compresses large costs;
the exact objective C remains the primary output and numeric-table quantity.
A cost with physical units would first need an explicit reference cost for
normalization; no implicit unit conversion is supplied.

The providers use the same UMD/CommonJS pattern as the rest of the application.
In a browser, load `math-terms.js` and `math-notation.js` before `math-index.js`, then load
`atlas-search.js` before the application composes them. Node callers can require
the providers directly. Adding a definition does not require editing the page
renderer or a playground module.

## Definition provider

```js
const index = AtlasMathIndex.create({cards, sources, stories});
const entry = index.get('delta-small');
const uses = index.forCard('function-composition');
const matches = index.search('projection', {category: 'linear'});
```

`cards` is the canonical card array; `sources` is the canonical source array,
not the surrounding source-document object. Optional `stories` supplies the
authored story array for mathematical labels, calculations and units. Creation
owns its projected data and does not mutate or freeze those inputs.

| Member | Contract |
|---|---|
| `entries` | Frozen array of projected entries |
| `categories` | Frozen `{id, title, count}` records for populated categories |
| `get(id)` | The complete frozen entry, or `null` for an unknown ID |
| `forCard(slug)` | Entries with identified uses in that actual card; unknown slugs return `[]` |
| `search(query, options)` | Ranked entry array; an empty query browses the collection |
| `markup(options)` | Escaped index HTML without listeners |
| `mount(host, options)` | Scoped view controller with `select(id)`, `getState()` and idempotent `destroy()` |

An entry exposes `id`, `title`, `category`, `symbols`, `aliases`, `lookupAliases`, `readAs`,
`definition`, `example`, `sources`, `usedBy`, `relatedIds` and `contextual`. Source records
contain a title and HTTPS URL. A usage record contains `slug`, `title`, `href`
and `contexts`; each context records a token, meaning, role, matching method
(`via`) and location. Grammar contexts also retain their declared type.

`search` accepts `category`, `mode` and `letter`. Category IDs are `operations`,
`language`, `functions`, `geometry`, `calculus`, `chance`, `dynamics`, `linear`,
`greek`, `notation`, `sets`, `discrete`, `units` and `card-notation`. The symbols mode limits results to entries with
notation. The A–Z view supplies an uppercase `letter` filter. The index caps a
query at 240 characters; matching is deterministic, without a remote service or
typo-correction model.

## Authored meanings and local usage

Authored definitions explain a concept in plain language and state a setting
when one matters. They include a spoken reading and a short original example.
Aliases should name that same concept: an outcome is distinct from an event,
and linear dependence is distinct from independence.

Card links are projected from explicit evidence rather than from arbitrary
substring searches through raw JSON:

| `via` | Evidence | Meaning shown to the reader |
|---|---|---|
| `grammar` | Exact `grammar.symbols[].token`, subject to authored token and card scopes | The card's own local role and meaning |
| `parameter` | Exact single ASCII-letter numeric `interactive.controls[].id`, only when that letter has no grammar definition in that card | An adjustable numeric model quantity; consult the playground expression and conditions |
| `formula` | An authored notation match in the formal formula, formation rule or worked expressions | That notation is present in the displayed mathematics |
| `notation` | A recognized glyph, structured expression, exposed helper or unit in selected canonical/story mathematical fields | That form is used in the identified mathematical or unit context |
| `term` | A word-boundary match in selected mathematical explanations, example assumptions/limits/checks, question answers or application prose | The term is named in that section |

Single letters are never inferred from prose substrings or incidental JSON
keys. The numeric-control rule covers, for example, `m` in Functional
Composition's `g(x)=mx+n`, even though its abstract grammar primarily names
`f`, `g` and `x`. Enum controls and names containing several letters do not enter
this fallback. A newly added numeric letter is included in the projected
Variable entry's symbols without changing the authored catalog.

An exact grammar token without an authored definition receives a stable
`notation-…` ID derived from its Unicode code points. Its `contextual` flag is
true, and its usage records preserve each card's own meaning. Its definition
sources come from those cards' source references. It does not invent a universal
meaning for a locally chosen name. Every current card grammar token is covered.

Formula matching uses bounded readers for declared notation families, not a
general TeX engine, symbolic algebra system or proof of semantic equivalence.
TeX command boundaries prevent `\le` from matching
`\left` and `\in` from matching `\infty`; full `\leq`, `\geq` and `\neq`
variants are included where appropriate. Authored `tokens`, `mathSymbols`,
`wordMatches` and `grammarCards` refine ambiguous matches. For example, `A` can
name amplitude or a matrix in different cards.

## Exact symbols and search scope

English names ignore ASCII capitalization. Exact mathematical notation preserves case:
`δ`, `Δ` and `∂` select distinct entries, while the English name `delta` can
return both lowercase and capital delta definitions. The reference explicitly
describes context dependence instead of assigning one universal value to a
Greek letter. Typed operators such as `-`, `*` and `/` have corresponding
entries alongside their displayed mathematical variants.

A bare ASCII-letter search keeps usage contexts for that exact letter,
including declared variables and units, rather than letters inside words. Its
returned entries are frozen projections with scoped `usedBy` lists. For example,
the Variable result for `m` retains its actual variable uses, while the unit
reference can separately identify metre uses. `get('variable')` still returns all
identified uses of the general Variable definition. Consumers should use the
search result's `usedBy` when presenting an exact-letter search; looking the ID
up again would intentionally retrieve the broader definition.

## Shared search, links and routes

```js
const search = AtlasSearch.create({cards, index, atlas});
const results = search.search('matrix', {kind: 'all', limit: 100});
```

The atlas argument is the existing atlas provider; its area search supplies map
results. Search results have `kind` (`term`, `card` or `area`), `id`, `title`,
`description` and `href`. Definition hits also expose their `entry` and
`symbols`; area hits include `availableCount`. The adapter searches at most 160
query characters and accepts a bounded result limit. An empty shared query
returns no hits and the full view offers starting suggestions.

The adapter ranks within each result type, then groups definitions, real cards
and areas. An area with zero available cards stays a map result with an explicit
availability count. It does not become a fabricated playable lesson. Exact
notation queries derive card matches from the index's identified usage. Spoken
readings such as `plus` can also connect definitions to their cards.

| Route | Purpose |
|---|---|
| `#index` | Browse the reference |
| `#index/<entryId>` | Open a definition |
| `#index/search/<encodedQuery>` | Search definitions |
| `#index/<entryId>/search/<encodedQuery>` | Preserve the selected definition and its symbol scope |
| `#search/<encodedQuery>` | Full shared search with result-type filters |
| `#card/<slug>` | Open a real card |
| `#atlas/map/<regionId>/<areaShortId>` | Open a map area |

Encode IDs and query components with `encodeURIComponent`. The common header
uses the compact shared-search view; Enter opens the full search page. Explore
retains its focused card search, and the index and map retain their own search
controls. The card's folded **Definitions** section uses `forCard`, displays
notation identified in that card, and links back to the appropriate definition
with symbol scope when available. It does not rewrite every word or number in
the story into a link.

## Mounting and cleanup

```js
const view = index.mount(host, {
  query: 'm',
  entryId: 'variable',
  onNavigate(state) { /* The application owns history updates. */ }
});
// Before replacing the host or leaving the page:
view.destroy();
```

The index mount accepts `query`, `entryId`, `category`, `mode`, `letter` and
`onNavigate`. State includes those selections and a navigation `reason`. Search
notifications use a null `entryId` so the application can retain the query route;
an explicit definition selection includes its ID. `getState()` returns a copy.
Native buttons and inputs support keyboard operation. Search updates retain the
input node, and keyboard definition selection restores focus to its result.
An unmatched search provides a clear-search recovery action.

`AtlasSearch` also provides `markup`, `resultsMarkup` and `mount`. A shared-search
mount accepts `query`, `compact`, `onOpen` and `onNavigate`, and returns `close`,
`getState` and `destroy`. Header suggestions close on Escape, link selection,
focus leaving the search or an outside pointer action. The compact view owns
one document pointer listener; all other listeners are scoped to its host.

Both controllers remove their listeners on `destroy`; repeated destruction is
safe. The application destroys page controllers before replacing their hosts
and closes header suggestions on navigation. Definitions, search queries and
filters do not write notebook or workspace data. Existing playground ownership
and clocks remain with the [shared module host](PLAYGROUND_MODULES.md).

## Extending the reference

1. Add a unique stable ID through the `add(...)` helper in
   [math-terms.js](../src/math-terms.js). Supply the title, category, symbols,
   plain-language definition, original example, reading and true aliases.
2. Add or reuse verified primary sources in its local source catalog, then name
   those keys in `sourceKeys`. Keep references attached to the claims they
   support; Greek character names alone do not establish every mathematical
   meaning assigned to those characters.
3. Specify `tokens` for exact grammar spellings, `mathSymbols` for formula
   notation, `wordMatches` for controlled text matching, or `grammarCards` when
   the same spelling has different meanings in different cards. Do not add a
   one-letter prose search or scan arbitrary serialized card data.
4. When adding a card, give its grammar tokens their actual local meanings and
   retain canonical definition sources. Register its mathematics, views and
   stories through the existing module architecture. The index and shared
   search then compose the available card data without a new page layout.
5. Extend the meaningful fixtures in
   [math-index.test.mjs](../tests/math-index.test.mjs) and
   [atlas-search.test.mjs](../tests/atlas-search.test.mjs), then rebuild the offline
   application. Check ambiguous symbols, exact card links, no-result recovery
   and keyboard focus as well as the new definition's wording. Extend bounded
   readers and run `node tools/check_notation.cjs` for every new mathematical
   form, exposed helper or unit; the full check writes the release inventory.

The reference embeds editorial learning aids and links to primary definition
sources. Reading the application works offline; opening an external source link
requires a connection. A usage match identifies vocabulary or notation in a
card, not an independently reviewed proof, historical priority claim or promise
of complete semantic indexing. Cards retain their draft status, mathematical
conditions and review gaps. See the [concept atlas contract](CONCEPT_ATLAS.md)
for the separate meaning of map relationships and planned concepts.

## Notation readers and the release gate (0.20.0)

`AtlasMathNotation` exposes `normalize`, `classify`, `extract`, `fieldsFor` and
`audit`. These functions operate on supplied data without storage, DOM access,
clocks, a remote service or arbitrary expression evaluation. They recognize
supported notation structures and retain the source spelling, location and
candidate definition IDs. They do not infer that every locally named quantity
has the same role in every card.

Exact queries include Unicode, typed and supported TeX spellings. Greek case,
capital letter versus n-ary operator (`Σ`/`∑`, `Π`/`∏`), prime forms and
context-sensitive bars remain distinct. A `\binom` layout can be a coordinate
column in Basis rather than a combinatorial coefficient. Layout commands are
classified as presentation, without inventing operators from matrix row breaks
or font wrappers. Scalar projection and vector projection retain different
definitions and outputs.

Unit fields are handled as units rather than incidental variables. `m/m` records
a slope ratio whose physical dimensions cancel, while retaining its meaning as
height change per horizontal distance. The chain story deliberately declares a
dimensionless design setting, so `m² per unit setting` is area sensitivity to
that declared setting. This is distinct from the canonical worked examples
whose setting is measured in metres; neither interpretation silently converts
the other's units.

`tools/check_notation.cjs` combines selected canonical/story fields, reference
examples and symbols, and public renderer/readout samples across declared
controls and views. `python tools/check.py` runs that gate and writes
`docs/NOTATION_COVERAGE_0_22_0.json`. The preserved 0.20.0 audit covered 18,000 fields,
29,760 occurrences and 826 normalized forms, with zero unresolved forms and
zero pending callable reviews. Its 664 formatting records and 58 reviewed UI
gesture-icon exclusions are accounted for separately. Counts describe this
finite corpus, not universal notation or independent mathematical review.

Definitions added with later concepts must arrive with sources, exact lookup
forms, local meanings, use evidence and regression cases. A new renderer label
can reopen notation work even without another canonical card. Related
definitions remain editorial navigation; they do not create atlas edges.

## Related definitions and notation priority (0.19.0)

Thirty-five authored entries supply `relatedIds`: arrays of stable definition
IDs. The projection owns and freezes those arrays, removes duplicates and
unknown/self references, and presents **Related definitions** separately from
**Cards that use this**. These are editorial learning suggestions, not formal
prerequisites, mathematical implications or newly inferred atlas edges. Tests
audit every authored reference so a misspelled ID cannot silently remove a link.

The related links open `#index/<entryId>` and use the ordinary page lifecycle.
They keep the reference useful even when a background definition has no current
card. Adding a definition and its related IDs needs no playground or page-specific
branch. Newly authored terms include linear/affine/convex combinations, span,
basis coordinates, rank, matrix dimensions, shear and matrix composition.

Exact known notation takes precedence over prose substrings, including more
than one ASCII letter. `AB` and `BA` resolve to Matrix product instead of matching
words such as absolute. The shared adapter retains that notation query in its
definition URL and finds cards through the index's actual usage evidence.
Known uppercase product queries also scope their card-use list to that exact
notation. A card merely naming matrix multiplication does not claim a local AB
token. Notation area hits come from areas containing those actual card uses,
rather than matching letter fragments in area names. Ordinary multiword searches
retain their ranked word matching.

Word-term evidence now includes explicit worked-example assumptions, conditions,
limits and independent-check prose, prompt questions/answers, application prose
and property conditions. These are selected learner-facing strings; arbitrary
JSON metadata and control keys are still excluded, and letters are never inferred
from prose substrings. This makes orthonormal, affine combination and convex
combination discoverable where the cards actually explain their conditions.
