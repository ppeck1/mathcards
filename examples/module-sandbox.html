One module. Two independent places to play.

The standalone growth frame module registers alongside the thirty-eight installed topics. Both panels below use the existing playground’s controls, presets, motion, readable numbers, comparison pin, and focus view. The host needs no topic-specific edit.

This is trusted local JavaScript using the module contract, and a developer demonstration outside the canonical reviewed-card catalog. Notebook capture is disabled here because this page has no notebook integration.

What this proves

  • Move a control, drag a shape handle, choose a preset, or animate one panel. Its peer retains its own parameters and motion state.
  • Both squares use a fixed scale of 20 pixels per side unit, so their areas are directly comparable. Setting q to zero collapses the square without changing the scale.
  • The module supplies validation, evaluation, controls, sweeps, presets, a view, and structured readout data. The shared host owns interaction, animation scheduling, pacing, and cleanup.
  • Each mount has its own slot and SVG namespace. This example adds growth-frame-sandbox through AtlasModules.register(); it adds no branch to the host.

The two small status lines count host change callbacks. They are diagnostics, not saved notes. The module itself creates no timer, animation loop, or event listener.
